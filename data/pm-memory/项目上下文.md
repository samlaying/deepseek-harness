## Skill 流程主线（5/27 确认）

```
访谈完成 → 生成搜索条件/关键词 → 搜索候选人
  → HR 审阅候选人列表
    → 【不满意】→ 追问原因 → 调整条件 / 继续找人
    → 【满意】→ 根据候选人数量推荐产品（影响人选/邀约）→ 生成 URL
```

- **访谈 Skill**：兜底问题（意向人员所需信息框架）必须集成；访谈结束由 Agent 自主判断
- **搜人 Skill**：搜索卡片含 A/B/C 组关键词组合；HR 反馈不满意时追问原因；防幻觉（无结果不能编造）
- **候选人列表兜底方案**：姓名 + 详情页 URL + 引导提示文案（暂不嵌入操作按钮）
- **商业产品推荐**：接口三参数 type + job_id + summary；候选人少→影响人选，多→邀约
- **意向沟通**：HR 口头指定候选人触发，job_id + res_id 拼接 URL；未指定职位时反问或拉取列表
- **候选人列表展示**：暂不嵌入操作按钮，仅提供姓名 + 详情链接 + 引导提示文案
- **导流埋点（5/28 确认，5/29 老板确认收窄）**：老板确认只需前端埋点 + 董涛生成短链 URL 实现归因，不需要后端"创建/发起"埋点；同会话内完成即算导流转化；区分"带访谈信息跳转"和"纯跳转"两类
- **P0 堵点**：搜索效果不稳定，关键词生成质量是核心问题
- **风险**：模型幻觉——即使 Prompt 约束"找不到可不找"，仍可能编造候选人
- **风险**：商业化产品推荐可能引起用户反感 `[新增]` 见 [[20260601 MT沟通-Skill流程技术方案对齐]]

## 技术方案细化（6/1 MT沟通）

- **职位类别预测**：两级机制——中台接口直接预测→失败则AI联想同义词重试→全部未命中引导手动选择
- **码表搜索**：不全量加载到Agent记忆，设计搜索工具按需模糊/正则匹配
- **Agent绑定**：持有job_id（非chat_id），记住绑定关系，不直接调SQL
- **访谈摘要生成**：参考Defy Pro模板，搜索"精准"时触发；调用链：摘要+职位基地→接口→返回1~2个URL（意向人选/邀约）→Markdown链接→用户点击跳转弹窗带入摘要
- **候选人触达产品矩阵**（扩展）：自行联系（云电话/IM）、发意向人选（URL）、发邀约（URL）、面试快（URL）、入职快（URL）
- **商业化引导决策**：面试快/入职快引导放Soul而非Skill，避免频繁推销感
- **外部依赖**：兑换页面设计稿（万里，周二）；访谈摘要接口（董浩）

## 2026-09-12 算力计费与消耗明细（对标WorkBuddy）产品机制与边界设计

- **核心机制与边界设计 (SSOT)**：
  1. **普通对话消息**：不加前置预计弹窗阻断；生成完毕后在气泡右下角展示「⚡ 实际消耗 X 算力」，Hover 查看 Prompt/Completion Token 拆解。
