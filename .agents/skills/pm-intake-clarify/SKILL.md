# PM 需求录入与动作拆解 (Intake & Clarify)

## 核心原则
1. **脑子只负责判断，不负责记忆**：将所有零散信息迅速归类到统一入口。
2. **不管理“任务”，只管理“下一步动作”**：拒绝抽象的“推进XX接入”，必须具体到“找XX文档确认是否支持XX”或“列出在XX场景下的差异对比”。如果坐下来还要思考怎么开始，说明还没拆完。
3. **今天只管 Top 3**：筛选出今天必须推动发生的 3 件结果，而不是 17 个待办。

## 执行步骤
1. 解析用户输入的原始想法/会议记录/反馈。
2. 提取出核心业务诉求与背景。
3. 拆解为原子级可执行的动作清单：
   - 动作描述 (动作 + 对象 + 交付物)
   - 依赖方 (谁欠我什么)
   - 建议截止时间
4. 标定是否属于 Today Top 3 范围。
